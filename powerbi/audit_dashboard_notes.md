# Power BI Audit Analytics Dashboard — Setup & DAX Reference

This document describes how to build the Power BI dashboard from the outputs
generated by the Python pipeline (`output/` folder) or directly from the SQL
queries.

---

## 1) Data Sources

Connect Power BI to one or both of:

| Source                            | Recommended Connection | Purpose                                     |
| --------------------------------- | ---------------------- | ------------------------------------------- |
| `output/exceptions_master.csv`    | Get Data > Text/CSV    | Main exception register (4 checks combined) |
| `output/summary_by_type.csv`      | Get Data > Text/CSV    | Exception counts by type/severity           |
| `output/summary_by_vendor.csv`    | Get Data > Text/CSV    | Exception counts by vendor                  |
| `output/data_quality_summary.csv` | Get Data > Text/CSV    | Data-quality metrics                        |
| SQL Server (staging tables)       | SQL Server connector   | Live/enterprise pipeline                    |

---

## 2) Data Model

Recommended star-schema layout:

- **Fact table:** `exceptions_master` (one row per exception, with `exception_id`)
- **Dimension tables:** `Date` (from `transaction_date`), `Vendor` (from vendor fields),
  `Severity` (from `severity` column)

Create a **Calendar** date table:

```dax
Calendar =
ADDCOLUMNS(
    CALENDAR(MIN(exceptions_master[transaction_date]),
             MAX(exceptions_master[transaction_date])),
    "Year", YEAR([Date]),
    "Month", FORMAT([Date], "YYYY-MM"),
    "MonthName", FORMAT([Date], "MMMM"),
    "Quarter", "Q" & QUARTER([Date]),
    "Weekday", FORMAT([Date], "dddd")
)
```

## 3) Key Measures (DAX)

```dax
Total Exceptions = COUNTROWS(exceptions_master)

High Severity Exceptions =
CALCULATE([Total Exceptions], exceptions_master[severity] = "High")

Exception Amount = SUM(exceptions_master[amount])

% High Severity =
DIVIDE([High Severity Exceptions], [Total Exceptions], 0)

Exceptions by Type = COUNTROWS(exceptions_master)

Duplicate Payments =
CALCULATE([Total Exceptions],
    exceptions_master[exception_type] = "Duplicate Payment")

Missing Invoices =
CALCULATE([Total Exceptions],
    exceptions_master[exception_type] = "Missing Invoice Number")

Out of Hours =
CALCULATE([Total Exceptions],
    exceptions_master[exception_type] = "Out-of-Hours Transaction")

Over Limit =
CALCULATE([Total Exceptions],
    exceptions_master[exception_type] = "Exceeds Approval Limit")
```

## 4) Suggested Visualisations

| Visual          | Configuration                                                           |
| --------------- | ----------------------------------------------------------------------- |
| **KPI Cards**   | Total Exceptions, High Severity, % High Severity                        |
| **Bar Chart**   | Exceptions by Type (exception_type)                                     |
| **Donut Chart** | Severity split (severity)                                               |
| **Line Chart**  | Exceptions over time (Calendar[Month] vs [Total Exceptions])            |
| **Table**       | Top risky vendors (vendor_name, [Exception Amount], [Total Exceptions]) |
| **Slicers**     | Severity, Exception Type, Month, Vendor                                 |

---

## 5) Exception-Based Reporting Principles

- **Risk-tiering:** Filter by `severity` to prioritise High first.
- **Drill-through:** From the "Exceptions by Type" chart, drill to the detail
  rows in `exceptions_master` to investigate the underlying transactions.
- **Row-level context:** Every exception links back to its `transaction_id`,
  enabling evidence-based follow-up.
- **Data quality gauge:** Show `data_quality_summary` to communicate dataset
  completeness to stakeholders.

---

## 6) Refresh & Automation

- Schedule dataset refresh in Power BI Service (daily/weekly).
- Re-run the Python pipeline (`python src/run_analysis.py`) to regenerate CSVs.
- For enterprise use, replace CSV import with the SQL Server connector and run
  the `sql/audit_exceptions.sql` queries as the source.
